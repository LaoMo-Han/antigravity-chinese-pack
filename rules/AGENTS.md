# Antigravity 简体中文核心交互与行为准则

本规则为 Antigravity 官方及通用开发环境下的中文交互标准。只要本插件处于启用状态，本规则全局始终生效。

---

## 1. 语言与沟通规范

1. **默认与深度中文交互**：
   - 所有的对话回复、方案阐述、逻辑推理、操作说明与问题解答，一律使用规范、现代、通顺的简体中文。
   - 避免机械生硬的字面翻译，表述应当自然、专业、符合中国开发者的阅读与编码习惯。
2. **中英双语专业术语标准对照**：
   在提及 Antigravity 及现代软件架构的核心概念时，统一遵循以下中文术语规范，必要时可在首次出现时标注英文原文：
   - **Workspace**：工作区
   - **Artifact / Artifacts**：制品 / 成果物
   - **Subagent**：子智能体
   - **Customizations**：自定义配置与扩展
   - **Plugin / Plugins**：插件
   - **Skill / Skills**：技能 / 能力模块
   - **Rule / Rules**：规则
   - **Hook / Hooks**：生命周期钩子
   - **Sidecar**：伴随进程 / 侧车扩展
   - **Slash Commands**：斜杠指令（例如 `/goal`、`/plan`、`/browser` 等）
   - **Model Selection**：模型选择
   - **Permission Grants**：权限预设与授权
   - **Terminal Sandbox**：终端安全沙箱
   - **Swarm**：多智能体蜂群协作
3. **保留原样的专业技术词汇**：
   - 编程语言、框架、库、协议及标准 API 名称（如 `React`, `TypeScript`, `Electron`, `Node.js`, `REST API`, `WebSocket`, `protobuf` 等）直接保持英文原名，不强行汉化。
   - 命令行指令、文件路径、代码变量与函数名必须保持原有拼写。

---

## 2. 编码与文档规范

1. **代码注释与文档**：
   - 在为用户编写、重构或补充代码注释时，注释内容均采用简体中文，解释关键逻辑、参数意义及边界条件。
   - 自动生成的 API 文档、README 或开发文档，优先输出中文版本，并保持目录和排版清晰整洁。
2. **错误排查与日志解读**：
   - 当终端执行报错、编译失败或调试日志出现异常时，智能体必须用中文详细解释错误的根本原因，并给出清晰、可执行的中文排查步骤与修复方案。
3. **排版格式规范**：
   - 严格遵循中英文混排规范：中文字符与英文单词、数字、代码块或超链接之间添加空格（例如：“在 `src/main.ts` 中配置选项”）。
   - 文件引用统一使用可点击的 Markdown 链接规范（如 `[main.ts](file:///...)`）。

---

## 3. 用户意图理解与交互优化

- 当用户使用中文输入简略需求时，主动结合当前工作区上下文进行结构化拆解，给出清晰的分步执行方案。
- 在涉及高风险操作（如覆盖配置文件、删除文件、终止后台进程）前，使用显眼醒目的中文提示（如引用块或注意警告）向用户说明影响范围并请求确认。
